# 超预测（Superforecasting）

## 概述

把模糊的大问题变成**可检验的数字概率**，登记入档，长期跟踪更新，到期结算并用 Brier 分数校准。核心信念一句话：

> **没有概率就没有校准，没有记分就没有学习。**

本技能的价值不在于"给出一个答案"，而在于**把每次判断变成可计分的一笔记录**——单次预测的成败近乎噪声，只有一揽子预测的长期表现才有信号。

## 何时使用

**使用**：
- 用户要判断"会不会发生 / 能不能成 / 成功率多大"，并希望得到一个带把握度的判断
- 用户面临重大决策（换赛道、创业、投大钱、跳槽、搬家）
- 用户要判断长期项目成败（做产品、带队伍、搞研发、追目标）
- 用户要更新已有预测、结算到期预测、或复盘校准
- 用户要把"我觉得大概能成"这类模糊直觉变成可检验的概率

**不使用**：
- 事实查询、查资料、写文档等非判断类任务
- 用户只想要一个安慰性的"肯定能成"（本技能不给情绪价值，会给数字和风险项）
- 已判定为钟表型（有现成规则答案）或云雾型且不重要的问题 → 在第 0 步直接给出对应出口，不启动全套流程

## 全局红线（每次都要遵守）

1. **禁用形容词概率**——"可能 / 大概率 / 很有可能 / 应该"一律换成数字
2. **基线先行不可颠倒**——先外部视角（历史基线），再做内部微调
3. **档案只追加不覆盖**——历史概率值永不修改，更新即新增记录
4. **AI 补充的假设必须打 `[AI补]` 标记**——不得伪装成用户的判断
5. **样本 < 20 条不下校准结论**——只展示台账
6. **重要但不可预测 → 走情景规划出口**，不硬给概率
7. **未经外部基线校验的内部结果，不得作为结论呈现**
8. **个人决策场景不下"该不该做"的判决**——只呈现分布、概率与逻辑
9. **总概率的任何变动必须可追溯**到某片叶子的状态变化或新的客观证据
10. **颗粒度要求 ≠ 虚假精确**——该精确的地方精确，不该精确的地方不许假装
11. **档位命名必须对齐权威标准**——量化档位（听力、视力、伤残、项目分期等）的名称与数值区间必须取自国标 / WHO / ISO，不得自行起名

完整红线清单与各步骤反例库见 `references/90-红线与反例库.md`。

```
输入：一个模糊的问题
  ↓

   🛑 **STOP** 停点：出口判定必须写给用户看；判为 C / D 时须等用户接受再收工
Step 1 锁直觉估计（封存，防污染）      → references/01-准入与锁直觉.md
   🛑 **STOP** 停点：直觉估计未锁定，不得进入 Step 2
  ↓
【阶段 B · 定价与输出】
Step 2 费米分解（结构化）             → references/02-费米分解.md
   🛑 **STOP** 停点：假设清单未锁定，不得进入 Step 3
Step 3 外部视角与参考类（找基线）      → references/03-外部视角与参考类.md
   🔴 CHECKPOINT：上位参考类 + 叶子基线表 + 来源清单 + 无基线标记，一次展示并等确认
Step 4 总概率锚定与瓶颈诊断（C+）      → references/04-概率锚定与诊断.md
   🛑 **STOP** 停点：总概率与敏感区间先交用户过目，不得径自入档
Step 5 颗粒度输出 + 直觉对照自检       → references/05-输出与登记.md
   🛑 **STOP** 停点：交付前 10 项自检逐项打勾；登记入档前须用户确认判定标准与截止日
  ↓
【阶段 C · 追踪与校准】（跨数周至数月）
Step 6 登记入档                       → references/05-输出与登记.md
Step 7 触发式更新                     → references/06-更新与结算.md
Step 8 到期结算（Brier）              → references/06-更新与结算.md
Step 9 复盘与校准                     → references/06-更新与结算.md
  ↓
闭环：复盘反哺下一轮的分解、参考类选择与差异点判断

> **每个 🛑 / 🔴 都是硬停点**：必须停下来等用户回应，不得一路跑完。多停一次的成本，远低于把整条流程跑偏的成本。
```

三条横贯支撑线**贯穿全程、不是独立步骤**：数据卫生、档案管理、评估校准。

### 场景归类（决定交付物形态、复核节奏与归档目录，**Step 5 前必须判定**）

按**「你是行动主体吗」+「结果形态」**两个问题判，取第一条命中：

| 场景 | 判据 | 交付物 | 复核节奏 | 归档目录 |
|---|---|---|---|---|
| **一 · 重大决策** | 待做**一次性取舍**，且结果不可逆（跳槽 / 创业 / 投大钱 / 搬家）| 射表式 HTML 报告（双层）| 事件驱动（按里程碑日）| `01-重大决策/` |
| **二 · 长期项目** | 你**已在做**，要判断能否达成（做产品 / 带队伍 / 搞研发 / 追目标）| 轻量 md 档案 + 概率曲线 | 固定周节奏 | `02-长期项目/` |
| **三 · 判断力训练** | 结果**与你无直接利害**，目的是练校准（时事判断 / 技术趋势 / 陪练题）| 档案 + 校准曲线 | 日 / 周 | `03-判断力训练/` |

**易混情形**：
- "跳槽去某公司，两年后它还活着吗" → 场景一（**决策**在前，虽含长跨度）
- "我做的产品两年后能盈利吗" → 场景二（**已投入**，是项目而非取舍）
- 两者都沾（"要不要投这个项目"）→ 按**是否已投入**切：未投入 → 一；已投入 → 二

> 判定结果须写入档案元信息与 `_ledger.json` 的 `scenario` 字段。**判错不影响正确性，但会让交付物与节奏错配。**

## 执行要领

### 第 0 步：先判断值不值得预测

过三道筛（影响大小与不可逆程度 / 可预测性是否落在钟表与云雾之间 / 时间跨度是否在几周到几年）。**四个出口**：

| 出口 | 条件 | 动作 |
|---|---|---|
| A | 钟表型，有现成规则答案 | 直接给规则答案，不走流程、不入档 |
| B | 三筛全过（金发姑娘区） | 走全套流程 |
| C | 影响极大且不可逆，但不可预测（云雾型） | **不给概率**，改做情景规划（2–4 个情景 + 触发信号 + 预案） |
| D | 影响小，**或**跨度远到无法中途验证**且**无合理里程碑 | 说明理由，劝退 |

**跨度大 ≠ 劝退**：时间跨度过长时，**先尝试切里程碑**（切得出即落到中短期，仍走流程）——**但滞后统计量类题除外**；**只有切不出可验证里程碑**、且影响不大时，才判 D。

**例外先判**：**滞后统计量**类题（人均预期寿命、人口结构、行业总量、因果链过长的宏观指标）——中途观测量与终点因果太长，**不是有效信号，不适用切里程碑**，直接按影响大小判 C（情景规划）或 D（劝退）。细则见 `references/01-准入与锁直觉.md`「时间跨度的处理」。

**预期**：多数问题会死在第 0 步，这是正常且正确的。详见 `references/01-准入与锁直觉.md`。

### 第 1 步：锁直觉估计（此后全程不得读取）

在引入任何基线之前，先拿到用户对这件事的**直觉估计**（点估计 + 区间 + 依据构成）并封存。用途只有一个：第 5 步与结构化结果对照，做**叙事谬误诊断**。

此步同时吸收了 `reference-class-forecasting` 技能自带的"锁内部估计"步骤——**调用该技能时，必须让它跳过自身的 Step 0**，否则会重复提问。

> **RCF 不可用也照样做**：本步自带四级阶梯与数据源白名单。**先探测** `~/.workbuddy/skills/reference-class-forecasting/` 是否可读（可读即算可用，不必真调用）；不可读时走 `references/03-外部视角与参考类.md` 的「RCF 不可用时的降级路径」，**不得跳过外部视角**（降级须在报告与档案留痕）。

### 第 2–4 步：三步定价，顺序不可颠倒

- **第 2 步 费米分解**：把问题拆成结构化、可检验的分解树（量值型用因数分解树、事件型用 AND/OR 必要条件树）。只标连接词，不做计算。
- **第 3 步 外部视角**：为每片叶子找同类事件的历史发生率，同时取到**总问题级上位参考类**（两者必须在同一次确认里锁定）。
- **第 4 步 总概率锚定（C+ 方案）**：**总概率锚定上位参考类，不做逐叶相乘**（逐叶相乘忽略共因失效，且产生虚假精确）。费米树退回去做两件擅长的事——**找差异点**与**诊断瓶颈**，只对 1–2 个头号瓶颈做局部条件追问。

### 第 5–6 步：输出并登记

输出形态按场景差异化（重大决策 → 射表式 HTML 报告；长期项目 → 轻量 md + 概率曲线；训练 → 档案 + 校准曲线）。交付前过 10 项自检门禁。档案按 `assets/档案模板.md` 建，编号 `F-YYYYMMDD-NN-短标题`，与机读总账 `_ledger.json` 同步维护。

### 第 7–9 步：让预测活着（**跨数周至数月，靠外部触发启动**）

三级触发（时间 / 事件 / 阈值）驱动更新；到期结算判定结果并算 Brier 分数；累积到 20 条后产出校准报告，把失败**归因到具体步骤**，定位系统性弱点。

**本阶段谁在什么时候启动它**（档案建完最容易被遗忘，故此三条必须明确）：

| 启动方式 | 触发条件 | 谁来做 |
|---|---|---|
| 定时提醒 | 每周一 09:00 | **automation**（只读汇报，绝不改概率、不结算）|
| 到期结算 | 判定日到达 | automation 提醒 → **用户主动说"结算"** → Agent 执行 V1–V4 |
| 被动识别 | 对话中出现与在追预测叶子/里程碑相关的信息 | Agent 主动问一次（**只问一次，不纠缠**）|

**automation 配置**：可直接安装的自包含 prompt 在 `references/06-更新与结算.md`「automation 配置（只读汇报）」节，照抄即可。全套动作细节（U1–U7 更新流程、V1–V4 结算流程、Brier/BSS/Murphy 计算）见 `references/06-更新与结算.md`。

> Python 报 `PermissionError`），导致后续无法更新。若已踩坑：先删除该文件，再用脚本重建。
> 本技能 `SKILL.md` 与 `references/` 下的文件同样可能被锁，改法相同。

## 档案体系（固定约定）

```
~/.workbuddy/forecast-archive/
├── _ledger.json          机读总账（数值索引权威）
├── _index.md             人读索引（按场景 / 状态分组）
├── _calibration.md       校准台账（每 20 条追加一份报告）
├── 01-重大决策/
│   └── F-YYYYMMDD-NN-短标题.md
├── 02-长期项目/
└── 03-判断力训练/
```

**权威归属**：`.md` 是内容权威，`_ledger.json` 是数值索引；两者冲突时以 `.md` 为准并回填 json。

**更新触发器**（由 automation 承担，只读不写）：**每周一 09:00** 检查一次——待结算 / 待复核 / 临近判定的条目，输出简报。**automation 绝不自动改概率、不自动结算。**（配置 prompt 见 `references/06-更新与结算.md`）

**报告与档案的关系**：档案 `.md` 是**内容权威（只追加，永不覆盖）**；重大决策场景的 HTML 报告是**可再生的呈现层（可用新版覆盖）**——报告里的任何数字都能从档案重建。报告须为**双层结构（大白话 + 专业解读）**，见 `references/05-输出与登记.md` §5.4。
